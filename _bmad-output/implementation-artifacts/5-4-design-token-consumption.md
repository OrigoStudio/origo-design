# Story 5.4: Design Token Consumption

## Story Requirements

**User Story:**
As a UI Developer,
I want the rendering primitives to natively consume Design Tokens,
So that the UI automatically respects the active theme generated in Epic 2.

**Acceptance Criteria:**
- **Given** the CSS custom properties generated by the Design Token pipeline
- **When** the Angular primitives render
- **Then** they correctly apply the semantic tokens (e.g., `var(--origo-color-surface)`) for styling, ensuring zero-code theming works out of the box (FR-Rend-003)
- **And** the primitives enforce strict CSS encapsulation (e.g., Shadow DOM or Emulated ViewEncapsulation) to prevent global style bleed from the host application.

**Business Context & Value:**
This enables zero-code white-labeling and theme switching across the entire Origo Design platform, ensuring all renderer components use a single source of truth for visual primitives without requiring code changes to the host application.

## Developer Context & Guardrails

### Technical Requirements
- Angular 18 Standalone Components (`standalone: true`).
- Reactivity MUST use Angular Signals (`signal()`, `computed()`, `effect()`) for component-local state.
- Zoneless-compatible implementation (no `zone.js` peer dependency).
- The primitives MUST consume CSS custom properties (design tokens) generated by Style Dictionary v4 (from Epic 2).
- Native CSS integration with Signals via host bindings (`[style.--token]`) or direct SCSS references.
- **CRITICAL**: Do NOT import `tokens.css` into individual component SCSS files. CSS custom properties pierce Shadow DOM boundaries if applied to `:host` or inherited from `:root`. Rely on inheritance to prevent CSS bloat.
- Expected Token Format Examples: `--color-surface-primary`, `--spacing-md`, `--radius-sm`, `--shadow-md`.

### Architecture Compliance
- **P1-AD-1:** Angular 18 Standalone Components + Signals. No RxJS except for Angular Router/HttpClient where no signal equivalent exists.
- **P1-AD-5:** Component Composition over Inheritance. Components must not extend each other.
- **P1-AD-6:** Accessibility Enforcement in CI. Ensure WCAG 2.1 AA compliance with Playwright axe-core tests.
- **AD-4:** Renderer isolation. Components must not import from other renderers, only from `@origo/core`.
- **AD-6:** Design Tokens Are the Only Source of Visual Primitives. No hardcoded colors, px values, or border-radius literals are permitted. All styling must use semantic tokens.

### Library & Framework Requirements
- Angular 18.x
- Style Dictionary v4 output tokens (from `@origo/design-tokens/dist/css/tokens.css`).
- Axe-core and Playwright for accessibility testing.

### File Structure Requirements
- Update `packages/angular-renderer/src/components/primitives/*`
- Angular component file structure: `name.component.ts` + `.html` + `.scss` + `.spec.ts` co-located.
- Use `origo-` prefix for component selectors (e.g., `origo-button`).

### Testing Requirements
- Unit tests (`*.spec.ts`) co-located with component source.
- Unit tests MUST explicitly verify that signal state changes correctly update the bound CSS variables on the host element.
- End-to-end component accessibility test using Playwright and Axe-core ensuring WCAG 2.1 AA minimum compliance. Test must fail CI if violated.
- Test selectors must use `metadata_path`.

## Latest Tech Information

**Angular 18 & Native CSS Signals:**
- Angular 18 supports binding Signals directly to CSS variables using host bindings to efficiently synchronize state to CSS without `zone.js` triggers.
- Example:
  ```typescript
  host: {
    '[style.--origo-color-surface]': 'surfaceColorSignal()'
  }
  ```
- Use `ViewEncapsulation.ShadowDom` or Angular's default emulated encapsulation to ensure strict CSS encapsulation and prevent style bleed.
