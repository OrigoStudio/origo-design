# Retrospective: Epic 8 - Diagnostics & DevTools (@origo/devtools)

**Date:** 2026-09-19
**Status:** Completed

## 1. Epic Review

### 1.1 Successes
- **Standalone DevTools Extension:** Successfully created a Manifest V3 Chrome Extension as a standalone Nx package in a single epic.
- **Production Safety:** Production tree-shaking guard (`isDevMode()`) securely strips the diagnostics API from production builds.
- **Data Redaction:** Effectively scrubs sensitive fields (`password`, `ssn`, `token`, etc.) before exposing state to DevTools.
- **UX Iteration:** Iteration on the inspector UI yielded a clean, highly usable interface featuring a virtualized component tree for navigating deep ASTs.

### 1.2 Challenges & Struggles
- **Manifest V3 Architecture:** The team struggled with ephemeral service workers silently dropping messages, connection maps blowing up with `NaN` keys, and getting the security permissions exactly right without violating CSP.
- **Test State Leaks:** Test state mutated globally across tests in Story 8-1, causing flaky test runs and requiring significant review time to track down.
- **Cyclic Object Graphs:** Deep object graphs with cyclic references caused stack overflows during early data redaction implementations.

### 1.3 Key Insights
- **Test Isolation Guardrails:** Global test state mutations are easy to introduce and hard to track down; strict isolation guards must be baked into the test infrastructure.
- **Extension Lifecycle:** Manifest V3 background workers require highly resilient reconnect logic to handle Chrome's aggressive suspending.

## 2. Next Epic Preparation (Epic 9)
Epic 9 will deliver a large batch of foundational primitive components (Form & Layout). The primary preparation requirement is to ensure the DevTools and Playground versioning strategy is tightly coupled with the core packages, guaranteeing these new primitives can be reliably inspected as they are rolled out.
