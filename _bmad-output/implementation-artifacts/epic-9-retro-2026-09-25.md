# Retrospective: Epic 9 - Form & Layout Primitives

**Date:** 2026-09-25
**Status:** Completed

## 1. Epic Review

### 1.1 Successes
- **Test Isolation:** The action item from Epic 8 (strict test isolation guards in `test-setup.ts`) successfully prevented all test state leaks across the 5 stories in Epic 9.
- **Design Token Architecture:** The CSS Custom Properties (`--origo-*`) pierced the Shadow DOM encapsulation flawlessly, allowing zero-code theme overrides across all 25 primitive components.
- **Delivery Velocity:** We successfully delivered 25 components in 5 batches without any major blockers.

### 1.2 Challenges & Struggles
- **Accessibility Semantics:** Reviewers consistently flagged issues with ARIA attributes (e.g., using `aria-live` instead of `role="alert"`, or messing up `<legend>` tags). 
- **RTL (Right-to-Left) Support:** The team repeatedly slipped up by using physical CSS properties (`padding-left`) instead of logical properties (`padding-inline-start`).
- **Overzealous HTML Sanitization:** We ran into bugs where valid string values (like dropdown selections or row IDs) were being dropped because they were aggressively sanitized as HTML.
- **Integration Gap:** The newly built components were not hooked up to the main Playground application, leaving us without a true end-to-end way to interact with them visually.

### 1.3 Key Insights
- **Testing Blind Spot:** Our Playwright a11y tests are currently bypassing the Angular component rendering and the Shadow DOM by injecting raw HTML strings. This gives us a false sense of security regarding accessibility.
- **Component Registry:** Expanding the `RENDERER_REGISTRY` mapping logic worked seamlessly to support all 25 primitives, validating our dynamic instantiation architecture from Epic 5.
