+# Branch Protection Rules (NFR-GIT-001)
+
+As part of the Origo Design architecture (Layered Hexagonal with Versioned Language Contract) and CI pipeline enforcement, it is critical that no code bypasses the CI checks. This ensures that formatting (Prettier), linting (Nx boundaries), and tests are consistently enforced before merging.
+
+To configure branch protection for the `main` branch, a repository administrator must apply the following settings in the GitHub repository settings.
+
+## Configuration Steps
+
+1. Go to the repository on GitHub.
+2. Click on **Settings** > **Branches**.
+3. Under "Branch protection rules", click **Add rule** or edit the existing rule for `main`.
+4. **Branch name pattern:** Enter `main`.
+5. **Protect matching branches:** Check the following options:
+   - **Require a pull request before merging:**
+     - Require approvals: Minimum 1 approval.
+     - Dismiss stale pull request approvals when new commits are pushed.
+   - **Require status checks to pass before merging:**
+     - Require branches to be up to date before merging.
+     - Add the status checks generated by the `.github/workflows/ci.yml` pipeline. Search for `main` (the job name in the CI file) or specific check names like `Run Nx Lint`, `Run Nx Test`, etc., and mark them as required.
+   - **Do not allow bypassing the above settings:** Ensure that even administrators are subject to these rules.
+6. Click **Save changes**.
+
+## Verification
+
+Once configured, any pull request to the `main` branch will display the status checks. If a status check fails (e.g., due to a boundary violation or failing tests), the PR cannot be merged until the issue is resolved and the check passes.
