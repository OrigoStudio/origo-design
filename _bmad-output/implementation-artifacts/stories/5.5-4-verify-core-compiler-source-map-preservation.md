# Story 5.5.4: Verify Core Compiler Source Map Preservation

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Core Developer,
I want to verify that the core compiler preserves source maps and line number offsets,
So that the upcoming CLI generator (Epic 6) can produce accurate error reporting.

## Acceptance Criteria

1. **Given** a compiled BADL schema
   **When** the compiler throws a validation error
   **Then** the error object includes the exact source map and line number offsets of the offending token
   **And** this behavior is verified by explicit test coverage.

## Tasks / Subtasks

- [x] Task 1: Research and analyze JSON parsing for source maps (AC: 1)
  - [x] Investigate how Ajv validation errors can be mapped back to line numbers. Standard JSON `JSON.parse` does not preserve source maps.
  - [x] Evaluate adopting a library like `json-source-map` or `jsonc-parser` in `@origo/core` to parse BADL schemas and retain location information.
- [x] Task 2: Implement Source Map Preservation in Core Compiler (AC: 1)
  - [x] Update the schema parsing logic (e.g., `packages/core/src/validator/index.ts` or `ast-validator.ts`) to track line and column offsets based on JSON pointers (e.g., Ajv's `instancePath`).
  - [x] When the validator encounters an error, enrich the error object with the source map offset (line, column).
  - [x] Ensure the error object format conforms to the standard `{ code: string, message: string, context?: object }` per conventions, attaching location details in the `context`.
- [x] Task 3: Regression and Integration Testing (AC: 1)
  - [x] Create explicit test fixtures to verify line number and offset accuracy when validation fails.
  - [x] Ensure the parsing speed meets `NFR-PERF-002` (completion under 30 seconds for a 500-entity application) despite the added parsing overhead.
  - [x] Run `nx test core` to ensure all existing tests pass, especially recursive schema coercion tests from Epic 5.5.3.

## Developer Guardrails & Architecture Compliance

### Architecture Rules
- **AD-1 (Layered Hexagonal)**: `@origo/core` must not import from any renderer or outer ring.
- **AD-3 (Grammar Package)**: No runtime dependencies on UI frameworks.
- **AD-7 (JSON is Canonical)**: BADL is stored as JSON. The parser must handle JSON and report line numbers for JSON.
- **Error Shape**: All packages must use `{ code: string, message: string, context?: object }`. Ensure the location information is added to the `context` object.

### Latest Tech Information
- **JSON Source Mapping**: Standard `JSON.parse` does not provide AST line numbers. You may need to add a dependency like `json-source-map` (which Ajv explicitly mentions supporting via JSON pointers) or `jsonc-parser` to map JSON Pointers (which Ajv outputs in its `instancePath`) to file line/column numbers.
- **Ajv `instancePath`**: Ajv 8 errors include an `instancePath` (e.g. `/properties/foo`). This JSON pointer can be used in conjunction with a source map to find the exact line and column of the error.

### Previous Story Intelligence
- **Story 5.5.3 (Recursive Schema Resolution)**: The previous story fixed property stripping by correcting AST coercion and Ajv options (`additionalProperties: false`). Ensure your updates to the validator do not revert these fixes. The validation engine (`ast-validator.ts` and `serializer.ts`) correctly handles recursive references without crashing.
