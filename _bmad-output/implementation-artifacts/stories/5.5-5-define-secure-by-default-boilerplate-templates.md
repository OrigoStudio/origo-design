# Story 5.5.5: Define Secure-by-Default Boilerplate Templates

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Developer,
I want secure-by-default boilerplate templates defined for the upcoming CLI generators,
So that generated code automatically adheres to security best practices without manual configuration.

## Acceptance Criteria

1. **Given** the template definition files for the CLI generator
   **When** the boilerplate templates are authored
   **Then** they must contain strict BADL Role-Based Access Control (RBAC) defaults (e.g., `permissions: { read: ["admin"], write: ["admin"] }`)
   **And** they are reviewed and approved for strict security compliance before being merged.

## Developer Guardrails & Architecture Compliance

### Architecture Rules
- **Templates output ONLY pure BADL JSON**: Templates must not contain framework-specific syntax.
- **JSON Is The Canonical BADL Format**: The entity templates MUST produce JSON files. Do not use YAML for templates.
- **Security**: Default security permissions in any template should fail closed (e.g., setting strict RBAC, denying capabilities unless explicitly permitted).

### Latest Tech Information
- **Template Generation**: DO NOT use external template engines like EJS, Handlebars, or Lodash. Use native TypeScript template literals or `JSON.stringify()` of typed objects to keep CLI dependencies minimal and prevent supply chain risks.

### Previous Story Intelligence
- **Epic 5.5.4 (Core Compiler Source Map Preservation)**: Validating the templates should produce proper source maps if any validation is run during template testing.
- **Epic 6.1 (CLI Initialization)**: `init.ts` currently hardcodes the `origo.json`. This should be replaced or informed by the templates defined here.

## Dev Notes
