# CLI Templates Guide

The `@origo/cli` provides scaffolding commands like `origo generate entity` to rapidly build out your application. These commands use built-in templates to ensure the code generated adheres to the strict architectural and structural rules of the Origo platform.

## Zero-Config by Default

By default, you do not need to configure or manage any templates. When you run a command like:

```bash
origo generate entity User
```

The CLI uses **internal templates** embedded directly inside the `@origo/cli` package. These templates are continuously tested against the core AST validator in our CI pipeline. This guarantees that any code generated by the CLI out-of-the-box is 100% compliant with the BADL schema and will compile without errors.

For 90% of use cases, this zero-configuration approach provides everything you need to be productive immediately.

## Customizing Templates (`--eject`)

If your team has specific requirements—such as adding standard corporate headers, customizing import aliases, or modifying the default boilerplate structure—you can take control of the templates by ejecting them into your local workspace.

To eject the templates, run:

```bash
origo generate --eject
```

### How Ejecting Works

1. **Extraction**: The CLI will copy all of its internal generation templates into a new `.origo/templates` directory in the root of your workspace.
2. **Prioritization**: On all subsequent `origo generate` commands, the CLI will first check if a template exists in `.origo/templates`. If it finds one, it will use your local template instead of the internal one.
3. **Modification**: You can freely edit the files inside `.origo/templates`. They use standard templating syntaxes (e.g., EJS or Handlebars) and receive the generation context (like entity names and fields) at runtime.

### Responsibilities When Using Custom Templates

While ejecting gives you ultimate flexibility, it also shifts the maintenance responsibility to you:

- **Architectural Drift**: If the Origo BADL schema introduces breaking changes in a future major version, you may need to manually update your ejected templates to remain compliant.
- **Validation**: The core compiler will still validate your generated output. If your custom template produces invalid schema, the AST validator will catch it and throw a compilation error.
